## Why it is built this way

<ul class="facts not-content">
  <li>
    <strong>The customer is in charge</strong>
    <span>They start the program, answer Windows, compare a code and allow control. Nothing happens to their computer before that, and one click stops it.</span>
  </li>
  <li>
    <strong>Your AI, your account</strong>
    <span>The agent runs where you already use it. No AI program, AI account or API key ever reaches the customer's computer.</span>
  </li>
  <li>
    <strong>Everything in sight</strong>
    <span>Both screens show every action as it happens: what really runs, why the agent says it runs, and how it ended.</span>
  </li>
  <li>
    <strong>Nothing left behind</strong>
    <span>The customer runs the program without installing it. At the end CretLink removes what it placed there and reports what it could not remove. Keeping the program for next time is the customer's own choice.</span>
  </li>
</ul>

## What it does today

- **Works:** a session between two computers on the same network, commands in PowerShell and Command Prompt, jobs you can follow and cancel, files in both directions with a check that the copy is identical, and a history of sessions with a report of each.
- **New:** sessions over the internet through [a relay that you host](/CretLink/relay/), a [file explorer](/CretLink/help-someone/#work-in-their-files) for the customer's computer, and a support program that a customer can [keep for next time](/CretLink/get-started/#a-customer-who-needs-help-more-often). The automated tests cover them. They have not been run between real computers yet.
- **Experimental:** screenshots, mouse, keyboard and clipboard of the customer's computer, and a terminal for the technician.

CretLink is open source under the MIT licence. It is a `0.x` pre-release: the [status in the README](https://github.com/yveslaurentcreton/CretLink#current-status) says what has been checked on real computers and what has not.
